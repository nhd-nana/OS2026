（实测 `si` 到 `pc=0x80200038, satp=0x8000000000080205` 后立刻回到 `0x80200000`，固件复位重来）。
QEMU 4.1.1 沿用旧行为，能正常跑完入口代码。→ **基线用 4.1.1**，QEMU 7 的适配留作实验后的额外成果。

## 5. 实现 page_init()

`kern/mm/pmm.c`，`//lab2 function1 <学号>` 位置：

```c
static void page_init(void) {
    va_pa_offset = PHYSICAL_MEMORY_OFFSET;          // 1. 虚实映射偏移

    uint64_t mem_base = get_memory_base();          // 2. DTB 报告的内存范围
    uint64_t mem_size = get_memory_size();
    if (mem_base == 0 || mem_size == 0)
        panic("page_init: invalid physical memory info from DTB");

    uint64_t mem_end = mem_base + mem_size;
    if (mem_end > PHYSICAL_MEMORY_END)              // 3. 不超过可管理上界
        mem_end = PHYSICAL_MEMORY_END;

    npage = PPN(mem_end);                           // 4. 页号上界（不含）

    extern char end[];
    pages = (struct Page *)ROUNDUP((uintptr_t)end, PGSIZE);   // 5. 描述符数组紧跟内核

    size_t page_num = npage - nbase;
    for (size_t i = 0; i < page_num; i++) {         // 6. 全部先标 Reserved
        pages[i].ref = 0; pages[i].property = 0; pages[i].flags = 0;
        SetPageReserved(&pages[i]);
    }

    uintptr_t pages_pa = PADDR((uintptr_t)pages);
    uintptr_t free_start = ROUNDUP(pages_pa + page_num * sizeof(struct Page), PGSIZE);

    if (free_start >= mem_end) return;              // 7. 没有完整空闲页就不注册

    init_memmap(pa2page(free_start), PPN(mem_end) - PPN(free_start));
}
```

要点（每一条都被 `test_page_init()` 检查）：

| 点              | 说明                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| 地址口径        | 内核跑在虚拟地址；`pages` / `end` 是**虚拟**地址，`page2pa()` / `PADDR()` 才得到物理地址 |
| `npage`       | `PPN(mem_base + mem_size)`，是**上界且不含**；`nbase = DRAM_BASE/PGSIZE = 0x80000`           |
| 保留            | OpenSBI（0x80000000–0x80200000）、内核镜像、描述符数组都不得进入空闲区                                |
| `init_memmap` | 传进去的页必须已是 `PageReserved`（`default_init_memmap` 里有 `assert(PageReserved(p))`）        |

## 6. 实现 Best-Fit

`kern/mm/best_fit_pmm.c` 骨架只给两个测试函数，管理函数要自己写。实现要点：

1. 内部状态：`static free_area_t free_area;` + `#define free_list (free_area.free_list)` / `#define nr_free (free_area.nr_free)`
   （测试函数直接用 `free_list` / `nr_free`，名字必须对上）
2. `init`：`list_init(&free_list); nr_free = 0;`
3. `init_memmap`：清标志 → `base->property = n` → `SetPageProperty(base)` → **按地址升序**插入链表
4. `alloc_pages`：遍历链表选 **`property >= n` 中最小**的块；块更大时切出尾部（`best + n`）留在原位之后，原块从链表删除
5. `free_pages`：按地址插入 → 与**前**块（`p + p->property == base`）、**后**块（`base + base->property == p`）合并
6. 注册：

```c
const struct pmm_manager best_fit_pmm_manager = {
    .name = "best_fit_pmm_manager",
    .init = best_fit_init,
    .init_memmap = best_fit_init_memmap,
    .alloc_pages = best_fit_alloc_pages,
    .free_pages = best_fit_free_pages,
    .nr_free_pages = best_fit_nr_free_pages,
    .check = best_fit_check,
};
```

7. 切换：`pmm.c` 的 `init_pmm_manager()` 里 `pmm_manager = &best_fit_pmm_manager;`
   （不改这里，跑的仍是 First-Fit，`[Test 2]` 会 FAIL）

### 9.1 Buddy System

## 10. 分支任务：双 GDB 调试页表查询

**目标**：在 QEMU 源码层面看"一条取指的虚拟地址如何被翻译成物理地址"。
一个 gdb 调内核（riscv 交叉版，走 gdbstub），另一个 gdb 调 QEMU 进程本身（x86_64 原生版）。

### 10.1 环境前提

| 项         | 要求                             | 检查命令                                                                       |
| ---------- | -------------------------------- | ------------------------------------------------------------------------------ |
| QEMU       | 带调试信息（`--enable-debug`） | `file $HOME/opt/qemu-4.1.1/bin/qemu-system-riscv64` 应含 `with debug_info` |
| QEMU 源码  | 与二进制同一次构建               | `ls $HOME/qemu-4.1.1-build/qemu-4.1.1/target/riscv/cpu_helper.c`             |
| x86_64 gdb | 调试 QEMU 本身                   | `gdb --version`（`sudo apt install gdb`）                                  |
| riscv gdb  | 调试内核                         | `riscv64-unknown-elf-gdb --version`                                          |

> `--enable-debug` 只加 `-g` 不加 `-O0`，部分局部变量被优化掉。用**行号断点 + 关键变量**
> （`addr` / `pte` / `ppn` / `idx` 都可用），不要指望 `next` 能稳定逐行走完。

### 10.2 一键演示

```bash
cd <仓库根>/code
./demo.sh mmu             # 自动跑完整演示，打印带标注的观察记录
./demo.sh mmu-manual      # 只打印三终端手工步骤与关键源码行号
KEEP_LOG=1 ./demo.sh mmu  # 保留 /tmp/lab2_mmu.* 下的 native.log / rv.log / serial.log
```

脚本做的事：

1. 用 gdb 启动 QEMU（`-s -S -monitor none -serial file:…`），**gdb 是 QEMU 的父进程**，
   因此不需要 `sudo`（`ptrace_scope=1` 只限制非子进程 attach）；
2. 在 QEMU 源码里下条件断点：`get_physical_address` 且 `addr == 0x80200000`（裸机阶段）、
   `addr == 0xffffffffc02000d6`（开分页后跳 `kern_init`）；
3. 另一个 riscv gdb 连上 gdbstub 让内核跑起来，命中后由 x86 gdb 打印查表过程。

### 10.3 手工三终端流程（指导书做法）

**终端 1**：起调试版 QEMU，复位即停

```bash
cd <仓库根>/code
make debug          # = qemu ... -kernel bin/ucore.img -s -S
```

**终端 2**：x86_64 gdb 附加到 QEMU

```bash
pgrep -f qemu-system-riscv64        # 取 PID
sudo gdb                            # ptrace_scope=1 时普通用户不能 attach
(gdb) attach <PID>
(gdb) handle SIGPIPE nostop noprint  # 不设这条，QEMU 的 SIGPIPE 会让 gdb 反复中断
(gdb) set pagination off
(gdb) dir ~/qemu-4.1.1-build/qemu-4.1.1
(gdb) break get_physical_address if addr == 0xffffffffc02000d6
(gdb) break ~/qemu-4.1.1-build/qemu-4.1.1/target/riscv/cpu_helper.c:256
(gdb) continue
```

**终端 3**：riscv gdb 连 gdbstub，让内核执行

```bash
cd <仓库根>/code
make gdb
(gdb) continue      # 内核一跑，终端 2 就命中断点
```

收尾：终端 2 `detach`，终端 3 `quit`，终端 1 里 `Ctrl+A` 松手再按 `X`。

### 10.5 这条路上踩过的坑

| 现象                                                 | 原因                                        | 解决                                     |
| ---------------------------------------------------- | ------------------------------------------- | ---------------------------------------- |
| `pkill -f qemu-system-riscv64` 把当前 shell 也杀了 | `-f` 匹配完整命令行，正好包含这条命令自身 | 用 `pkill -x qemu-system-riscv64`      |
| attach 后 gdb 频繁停在 SIGPIPE                       | QEMU 内部会收到 SIGPIPE                     | `handle SIGPIPE nostop noprint`        |
| gdb 找不到源码                                       | 没设源码目录                                | `dir <QEMU 源码目录>`                  |
| 串口输出与 gdb 输出混在一起                          | 没重定向串口                                | `-serial file:...` + `-monitor none` |
| `next` 跳来跳去                                    | 只加了 `-g` 没加 `-O0`                  | 行号断点 + 打印关键变量                  |

## 11. 坑与经验（按踩到的顺序）

| 现象                                                                  | 原因                                                                               | 解决                                                                                                   |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| QEMU 7 下内核启用 Sv39 后立刻复位                                     | 物理 PC 在新页表中无映射；7.0 写 satp 后立即重翻译                                 | 用 QEMU 4.1.1（基线）；QEMU 7 需给入口代码加恒等映射，留作实验后                                       |
