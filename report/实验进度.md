## 环境决策（2026-10-20）

**结论：基线用指导书同代 QEMU 4.1.1（含 `--enable-debug`），QEMU 7 兼容性作为实验后的额外成果。**

### 触发原因（实测证据）

在 QEMU 7.0.0 + OpenSBI v1.0 下，lab2 内核执行到 `entry.S` 开分页后立即异常并复位：

```
si 12 → pc=0x8020002e  satp=0                 ← 物理地址上执行，正常
si  3 → pc=0x80200038  satp=0x8000000000080205 ← csrw satp 已生效
si  1 → pc=0x80200000                          ← 立即回到入口（异常 → 固件复位）
```

原因：`entry.S` 在物理地址 `0x80200xxx` 上 `csrw satp` 打开 Sv39，而页表只映射 `0xFFFFFFFFC0000000+`；
物理 PC 在新页表里无映射 → 下一条取指 instruction page fault。
老版本 QEMU 依赖"已翻译的 TB 继续执行"这一实现细节，7.0 写入 satp 后重新翻译，故失败。

### 决策依据

| 维度 | QEMU 7（开创） | QEMU 4.1.1（妥协） |
|---|---|---|
| 每章成本 | 每章先要区分"代码错"还是"模拟器变"；lab3 中断/定时器、lab5 ecall、lab9 换页都依赖特权级与 SBI 语义 | 按指导书推进，问题基本都是自己的 bug |
| 成绩风险 | 某章修不动就卡住 | 低 |
| 答辩 | 助教按指导书提问，解释成本高 | 对齐 |
| 收益 | 兼容性报告 + 补丁（助教明确说有价值） | 无，但 **lab2 分支任务本就要求自编译带 `--enable-debug` 的 QEMU**，编译流程现成 |

→ 先保交付；QEMU 7 的恒等映射补丁与逐章验证放到实验完成后，作为独立成果交给助教。

## 实现要点备忘（做题时用）

### page_init() 关键信息

| 项 | 值 / 来源 |
|---|---|
| `va_pa_offset` | `PHYSICAL_MEMORY_OFFSET` = `0xFFFFFFFF40000000` |
| 物理内存范围 | `get_memory_base()` / `get_memory_size()`（来自 DTB，`dtb_init()` 已在 `kern_init()` 里调用） |
| `npage` | `PPN(mem_base + mem_size)`；测试要求 `npage > nbase`（`nbase = DRAM_BASE/PGSIZE = 0x80000`） |
| `pages` 起点 | `ROUNDUP(end, PGSIZE)`（虚拟地址；`end` 是链接符号） |
| 描述符大小 | `sizeof(struct Page) * (npage - nbase)` |
| 保留页 | 内核尾部页（`pa2page(PADDR(end))`）与描述符数组自身所在页 → `SetPageReserved` |
| 注册空闲区 | `init_memmap(pa2page(free_pa), n)`；`n == 0` 时不得调用 |

### 地址关系

```
虚拟地址 = 物理地址 + 0xFFFFFFFF40000000
KERNBASE = 0xFFFFFFFFC0200000   （对应物理 0x80200000）
page2ppn(page) = page - pages + nbase
```
